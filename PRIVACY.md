# Privacy Statement

## Overview

Clinical Note Tool is designed with a local-first approach. The purpose of this project is to provide clinicians with a simple documentation support tool while minimizing unnecessary transmission of sensitive information.

This document explains how information is handled when using this software.

## Data Storage

Clinical Note Tool is designed to operate locally on the user's device.

The application does not require a user account, cloud storage service, or external database to function.

Information entered into the application is intended to remain on the user's device unless the user chooses to copy, export, save, or share that information through another method.

## Collection of Information

Clinical Note Tool does not intentionally collect, transmit, or store user-entered clinical information.

The software does not include built-in analytics, tracking systems, advertising services, or third-party data collection features.

## User Responsibility

Users are responsible for maintaining appropriate privacy and security practices when using this software.

This includes:

* Protecting access to the device where the software is used
* Following organizational privacy and security policies
* Determining whether use of the software is appropriate for their professional setting
* Avoiding the unnecessary entry of sensitive information

Users should only enter protected health information (PHI) or other confidential information when they have determined that doing so is appropriate and consistent with applicable requirements.

## Third-Party Services

Clinical Note Tool does not require integration with third-party services.

If users modify the software or connect it with external services, those services may have their own privacy practices and requirements.

Users are responsible for evaluating any additional tools, integrations, or modifications they choose to use.

## Open Source Development

Because this project is open source, users and developers may review, modify, and improve the software.

Transparency and community review are important parts of the project's development philosophy.

## Security Considerations

While the project is designed with privacy in mind, no software can guarantee complete security.

Users should evaluate the tool within their own environment and consider factors such as:

* Device security
* Operating system updates
* Access controls
* Backup practices
* Organizational requirements

## Future Changes

As the project develops, additional features may be added. Any future features involving data storage, external services, or information sharing should be evaluated carefully and documented.
